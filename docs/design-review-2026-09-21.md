# JBJI 课表助手 · 设计评估与局部重构

2026-09-21 · 以学生查课与排课为中心

**结论：保留整体设计，修整信息层级和操作反馈。没有必要推倒重做。**

网站已经具备清晰的产品定位、连贯的色彩体系和完整的核心流程。值得改善的不是“像不像一个新网站”，而是学生在小屏幕上能否更早看到课表、能否知道当前显示了哪些课程、能否安心地试排一门课。

**评估依据与边界**

仓库说明把目标定义为：将学院合并课表按学位、年级、专业和班级拆开，方便日常查课和下载。此次核对 GitHub main 为 `f05f58457e074b2363cc47a1878442229003ae2b`，与本地改动前版本一致，包含最近加入的缩放和适应宽度功能。

在本地运行完整 React 网站，查看了原版桌面和 390×844 手机页面，实际操作“查课 → 搜索 Matlab → 完成”；改动后复核了同一手机筛选状态及 1440×960 桌面布局。它不是只依据截图的评价，也不是线上部署验收。没有进行真实学生访谈或任务计时，以下区分实际观察、源码证据和设计判断，不提供伪精确的满意度评分。

**从三个使用情境衡量设计**

| 情境 | 学生最需要知道什么 | 设计应该优先提供什么 |
|---|---|---|
| 学期初建立课表 | 我的班、哪些课程需要手动添加、有没有冲突 | 明确的身份选择、整学期分布、可撤销的试排 |
| 平时快速查课 | 今天或指定一天几点上课、在哪里 | 日期与周次、课程名和教室、容易切换的日视图 |
| 保存个人课表 | 下载包含哪些课程，临时编辑是否改动公共数据 | 清楚的导出范围，预览与正式课表的边界 |

这三种用途有不同的信息密度。整学期周视图适合比较分布，日视图适合阅读详细安排。因此保留已有双视图，不把手机强制改成日视图，也不默认把整张周课表缩成难以辨认的小字。

**原设计值得保留的部分**

| 维度 | 评价及理由 |
|---|---|
| 功能组织 | “身份 → 课表 → 选课与导出”的顺序合理。选修、重修进课程面板，资料与帮助分离，没有必要增加宣传首页或复杂引导。 |
| 空间与排版 | 身份筛选和课表两个主要区域容易辨认。课表的时间轴、午间分隔、课程卡片保留了熟悉的纸质课表结构，学习成本低。 |
| UI 一致性 | 预览、已选、冲突、个人编辑版已有明确设计基础；课程详情和原始资料也能提供进一步确认。局部交互需要对齐，而非重造流程。 |
| 配色 | 暖白底、暨伯橙主操作、低饱和课程底色相互协调。较鲜明的颜色集中于选择与操作，课程区的大面积淡色适合承载密集文字。九套主题应保留。 |
| 信息密度 | 课程名、教室、周次、教师都有使用价值。贸然删除信息或把全部文字放大会破坏并列排课，应通过层级、颜色和详情入口处理密度。 |
| 校园气质 | 双院徽与奶龙给工具带来熟悉感和作者个性。无需把它改成通用办公软件；更合理的是调整这些内容出现的位置与频率。 |

橙色是否让某个学生更舒适属于个人偏好，不能将其包装成普遍的心理学事实。这里保留橙色的理由是已有品牌连续性、视觉协调和足够的主按钮文字对比度。个体差异由现有主题选择承接。

**本轮实际重构**

| 改进 | 原版证据 | 实施方式与取舍 |
|---|---|---|
| 手机首屏空间 | 390px 宽度下顶部约 151.8px，品牌、工具链接、两条下载链接分三行，且顶部保持粘性。 | 手机导航缩为“院徽与品牌 / 配色 / 更多”，高度实测 64px，释放约 88px；资料、帮助、GitHub 与两张奶龙原图完整保留在更多面板。桌面继续展示原有入口。代价是手机低频功能多一次展开操作。 |
| 持续可见的筛选状态 | 实测搜索 Matlab 并关闭面板后只剩两个上课安排，页面没有常驻筛选说明。 | 增加“正在筛选”标签、逐项清除和清除全部；重新打开查课不再暗中重置。无筛选时不占空间，清除课程筛选时保留当前周次。 |
| 可触摸的重修预览 | 原重修预览只绑定鼠标进入/离开；选修已具有显式预览按钮。 | 重修补“预览课表 / 取消预览”，课表区显示预览管理条，可加入或返回课程面板。在覆盖式抽屉宽度下，预览后关闭抽屉，避免遮住结果。 |
| 预览与导出边界 | 导出按当前显示范围生成，原菜单未充分说明筛选范围；课程预览可能影响冲突样式。 | 菜单显示具体范围及可导出的上课安排数量；空结果禁用导出。预览不保存、不导出；导出时按实际已选课程重新确定冲突样式，剔除交互提示。 |
| 导出菜单收起 | 交互验收发现：开始生成文件后菜单仍展开，遮住下方课表操作。 | 开始导出即收起并将焦点交还“导出课表”；补齐点击外部、焦点移出与 Escape 关闭。生成进度继续显示在页面上。 |
| 冲突信息可读性 | 源码中部分冲突条目及周次仍为 7.5–10px，重修冲突状态为 8px。 | 冲突标题 14px、课程对 13px、时间和说明 12px，行高 1.5。学生首先应该读清哪两门课、哪天、哪些周发生冲突。 |
| 辅助文字对比 | 分类标签的 0.75 透明度使九套预设主题上的计算对比约为 2.82–3.25:1。 | 恢复不透明，使用既有更深文字变量，预设课程底色上的计算对比提升至约 5.45:1 以上。课程底色和主色不变。 |
| 触摸与键盘 | 手机重修操作按钮约 27px 高；详情弹窗缺少 Tab 循环和关闭后的焦点恢复。 | 手机重修按钮和筛选胶囊补齐 44px 操作高度；身份与面板按钮表达选中状态；详情约束 Tab 焦点并恢复触发点。44px是舒适度目标，不将原来所有较小控件一概判为违反标准。 |

**设计语言与空间分配**

颜色继续沿用现有语义：暖白纸面 `#F7F6F4`、白色内容面、橙色操作 `#BD570C`、深棕正文 `#39342F`。伯大、暨大、英语、通识课程继续使用各自淡色底和边缘色条；危险或冲突使用独立警示色，且始终伴随文字。

从空间设计看，长期可见的导航占用了最昂贵的手机垂直空间。将资料和下载归入更多，是按使用频率分配位置；让课表更早出现，同时保留低频内容的可达性。筛选提示则只在需要时出现，因为它占据空间的同时，能够解释“为什么课表变少了”。

从认知负担看，持续显示筛选词减少了记忆要求；明确的试排和取消动作减少了“我是不是已经选上了”的猜测。它们比装饰性动画、大标题或更多卡片更符合这个工具的用途。

**本轮不建议扩大修改的地方**

- 不重新设计九套主题，也不为了追求“高级感”改成全灰、玻璃效果或大面积深色。
- 不把整学期或周视图的默认值改掉。最近的仓库提交专门选择了整学期默认，这也符合学期排课目的。
- 不让“适应宽度”成为手机默认。900px课表缩进约340px空间后，14px课名视觉上约为5.3px，只适合总览分布。
- 不增加首页宣传区、账号系统、复杂导航层级，也不调整课程数据、周次规则和正式选课边界。
- “下一节课是否应该始终展开”和“是否记住日/周偏好”留作真实学生使用反馈后的决策。本轮没有证据证明所有学生都希望改变这些默认行为。

**验证情况**

- 已通过：`npm run build`，包含 TypeScript 检查和 Vite 生产构建。
- 已通过：`node --test --test-isolation=none tests/*.test.mjs`，32 项原有测试；包括课程来源、56 个身份组合与 20 周安排、冲突规则、主题及个人编辑逻辑。使用无进程隔离模式是因为当前环境限制子进程启动。
- 已实际观察：原版桌面与390px手机页面、原版搜索后隐藏筛选状态、改版后的持续筛选提示、手机64px顶部、1440px桌面布局。
- 已完成重修交互：在大二、双学位、ICS1 身份下预览“军事理论与国家安全教育”，抽屉自动收起，显示两处“预览冲突”；加入后变为“已加入冲突”，重修计数增为 1；移除后课程及两处冲突都消失。
- 已完成筛选交互：搜索 Matlab 得到两个上课安排，关闭及重新打开课程面板后仍保留搜索词；搜索不存在的长字符串时，图片、PDF、编辑后导出三个入口均禁用，菜单解释空结果原因；清除筛选恢复完整课表。
- 已完成窄屏检查：320×740 浏览器视口下，顶部高度 64px，普通页面内容宽 305px（其余为浏览器滚动条），没有整页横向溢出；长筛选词正常换行，272px 更多菜单在屏幕内，五个资源入口完整；重修按钮实测高 44px。课表本身保留有意设计的内部滚动。
- 已完成键盘检查：课程详情打开后焦点在关闭按钮；Tab 到反馈链接，再次 Tab 回关闭按钮；Shift+Tab 反向循环；Escape 关闭后焦点恢复到原课程卡片。重修抽屉 Escape 后焦点回到“重修”，页面恢复滚动。手机更多菜单及导出菜单 Escape 后焦点均回到各自入口，更多菜单点击外部能关闭。
- 已完成真实文件检查：在屏幕存在两处重修预览冲突时，通过页面分别下载 PNG 和 PDF；PNG 为 3720×5535，PDF 为单页 A4 纵向。逐张查看 PNG 与 PDF 渲染图，预览课程、临时冲突提示和冲突样式均未混入，正文没有可见裁切。另在 320px 视口搜索 Matlab 后实际导出 PNG（3720×3984），仅含两个匹配安排，完整五日表格未受手机内部滚动影响。导出样本另存于项目上级的“验收输出”目录。
- 菜单修复已实测：生成图片时立即收起导出菜单，焦点回到“导出课表”，页面继续显示生成状态；修复后重新通过生产构建、32 项测试及 `git diff --check`。
- 边界：以上为本机浏览器的实际交互和视口模拟，不等于真实手机触控、Safari 或屏幕阅读器兼容性认证。网络审批服务间歇中断后经重试恢复，原先列出的主要交互验收现已完成。

本报告记录发布前的本地设计与验收结果。改动保留核心功能，同时提供可审查的局部改进；线上发布状态以对应提交的 GitHub Pages 部署记录为准。

后续只需请几位不同年级的同学完成三件事：查看自己的下一次课并说出教室；试排一门有冲突的重修并取消；搜索一门课后说明将导出什么。观察是否迷路、是否误以为预览已生效、是否找不到清除入口，比继续凭设计师个人偏好换皮更有价值。
